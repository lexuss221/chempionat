# Пошаговая инструкция по выполнению модуля А

Вам нужно самостоятельно превратить HTML-карточки и CSV-файлы в связанную базу данных PostgreSQL. Итог работы — ваши скрипты, заполненные таблицы и доказательства качества данных. В этой инструкции приведён порядок работы; алгоритмы и код решения вы разрабатываете сами.

Сначала пройдите упражнение в удобном темпе. Повторный проход выполните за конкурсные 3 часа. Установку программ и первоначальную настройку окружения на первой тренировке выполняйте до начала отсчёта.

## Шаг 1 Подготовьте рабочую папку

Работайте со своей копией всей папки `student`. Откройте её в редакторе кода и откройте PowerShell в этой же папке. Во всех командах ниже текущая папка — `student`, если явно не сказано другое.

Проверьте, что программы доступны:

```powershell
python --version
docker compose version
```

Нужен Python 3.11 или выше. Если команда `python` не найдена, обратитесь к преподавателю для настройки Python. Docker Desktop должен быть запущен в режиме Linux containers.

Создайте виртуальное окружение:

```powershell
python -m venv .venv
```

Для запуска Python используйте явный путь, тогда активация окружения не требуется:

```powershell
./.venv/Scripts/python.exe --version
```

Рабочие файлы размещайте в `work/Rep1`. Удобная структура:

```text
work/Rep1/
  README.md
  requirements.txt
  src/
  sql/
  output/
  reports/
```

Создайте эти папки и файлы по мере необходимости. В `src` будут ваши Python-скрипты, в `sql` — создание таблиц и проверки, в `output` — результаты обработки, в `reports` — описание модели и отчёт качества. Окружение `.venv` сдавать не нужно.

**Проверьте себя:** вы понимаете, где находятся исходники и куда будете сохранять собственные результаты. Файлы `data/input` не изменены.

## Шаг 2 Запустите пустую базу

В PowerShell выполните:

```powershell
./start.ps1
docker compose ps
```

Дождитесь готовности контейнера. Состояние health должно быть `healthy`. Если запуск скрипта запрещён настройками компьютера, используйте ручной вариант из `README.md`, не меняя политики безопасности компьютера без преподавателя.

Подключитесь через pgAdmin или DBeaver:

| Поле | Значение по умолчанию |
|---|---|
| Host | localhost |
| Port | 5434 |
| Database | student |
| User | student |
| Password | Значение POSTGRES_PASSWORD в вашем .env |

Другой вариант — консоль psql:

```powershell
docker compose exec db psql -U student -d student
```

В SQL-редакторе или psql выполните:

```sql
SELECT current_database(), current_user;
```

Убедитесь, что это ваша учебная база. В psql команда `\q` возвращает в PowerShell.

Если на одном компьютере работают несколько студентов, до первого запуска настройте разные имена проектов и порты по `README.md`.

**Проверьте себя:** вы подключились к базе и можете выполнить SQL. Таблицы задания ещё не созданы — это ваша работа.

## Шаг 3 Изучите данные и составьте план модели

Откройте `Задание_модуль_А.md`. Затем откройте в браузере `data/input/html/index.html`, перейдите в реестр и изучите одну карточку компетенции. Посмотрите её HTML-код в редакторе.

Для каждого CSV из `data/input/tables` просмотрите заголовки и несколько строк. Не сохраняйте CSV из Excel поверх оригиналов: программа может изменить кодировку или идентификаторы.

Запишите в `reports/model.md`:

1. Какие сущности представлены в наборе.
2. Что означает одна строка каждой исходной таблицы.
3. Какой столбец или набор столбцов должен быть уникальным.
4. Какие поля связывают таблицы.
5. Какие поля числовые, а какие нужно сохранить текстовыми.

Начните словарь данных со столбцами «Таблица», «Поле», «Смысл», «Тип», «Обязательность», «Связь». Заполняйте его по мере работы.

Особое внимание уделите `result_id`, `comp_id`, `event_id`, `region_id` и `source_page`. Названия объектов могут повторяться и не всегда подходят в качестве ключей. Регион-лидер из карточки — отдельный атрибут; не подменяйте им регион участия из фактов.

**Проверьте себя:** вы можете объяснить, как связать один результат с компетенцией, событием и регионом, а новость — с событием.

## Шаг 4 Прочитайте базовые таблицы программно

Создайте собственный скрипт чтения данных в `src`. Для CSV можно использовать стандартный модуль `csv`; другие библиотеки выбирайте самостоятельно. Если нужны дополнительные пакеты, устанавливайте их через Python вашего окружения и фиксируйте названия и версии в `requirements.txt`.

В скрипте реализуйте:

1. Получение пути к исходной папке.
2. Чтение CSV с корректной кодировкой и разделителем. Учтите возможный BOM в начале файла.
3. Проверку наличия ожидаемых заголовков.
4. Подсчёт прочитанных строк по каждому файлу.
5. Сохранение идентификаторов без потери символов и ведущих нулей.

Запускайте свой файл из папки `student`, например:

```powershell
./.venv/Scripts/python.exe work/Rep1/src/read_sources.py
```

`read_sources.py` — пример имени вашего будущего файла, его нет в комплекте. Аналогично все последующие имена скриптов вы выбираете и создаёте сами.

Пока не удаляйте строки и не заменяйте пропуски. Сначала зафиксируйте исходное состояние.

**Проверьте себя:** программа читает все таблицы, показывает их размеры и заголовки; кириллица отображается корректно.

## Шаг 5 Напишите парсер компетенций

Начните с одной HTML-карточки. Определите, какие элементы содержат название поля и его значение. Используйте HTML-парсер; не полагайтесь только на видимую строку страницы или её порядковый номер.

Извлеките семь атрибутов:

- `comp_id`;
- название;
- категорию;
- регион-лидер;
- краткое описание;
- статус;
- комментарий.

После успешной обработки одной карточки организуйте обход ссылок из реестра на все карточки. Учтите, что одна страница может встретиться повторно. Не зашивайте в программу список идентификаторов и число карточек.

Результат сохраните в структурированном виде, например CSV. Для записи оставляйте информацию об исходном файле, чтобы можно было проверить происхождение данных.

**Проверьте себя:** сравните поля в нескольких строках результата с исходными HTML вручную. Парсер обрабатывает все карточки и сохраняет текст без HTML-тегов и лишних пробелов.

## Шаг 6 Сопоставьте ссылки с событиями

Из каждой карточки извлеките ссылки на связанные события. Вам нужны пары «компетенция — событие», а не содержимое страниц событий.

В этом наборе адрес в карточке может быть относительным и содержать якорь. Выполните следующие действия:

1. Разрешите относительный адрес относительно расположения карточки.
2. Отделите якорь после `#` от адреса страницы.
3. Приведите адрес и `base_events.source_page` к сопоставимому виду.
4. Найдите соответствующий `event_id`.
5. Сохраните пары `comp_id`, `event_id` отдельно от справочника компетенций.

Страницы событий в комплекте отсутствуют намеренно. Не пытайтесь открыть каждую такую ссылку как локальный файл. Не определяйте `event_id` угадыванием по тексту ссылки: сопоставление должно опираться на `source_page`.

Если ссылка не сопоставилась или соответствует нескольким событиям, сохраните её в журнал проблем. Не выбирайте первую случайную запись.

**Проверьте себя:** для каждой пары можно показать карточку-источник и строку события. Повторная ссылка не создаёт повторную пару.

## Шаг 7 Подготовьте данные и выполните предварительные проверки

Сохраните исходные значения и сформулируйте правила очистки до их применения. Программно обработайте пробелы, пустые значения и числовые поля. Не подменяйте неизвестное значение нулём без обоснования.

Разделяйте два случая:

- полностью одинаковая повторная запись;
- одинаковый ключ при различающихся значениях остальных полей.

Они требуют разных решений. Конфликт нельзя устранить случайным выбором одной строки. Числовые идентификаторы не обязательно означают числовой тип: арифметика над кодами обычно не нужна.

Проверьте связи между фактами и справочниками, между текстами и их объектами, между компетенциями и событиями. Наличие внешнего ключа в будущей БД не заменяет предварительный отчёт о проблемах.

Ведите журнал со столбцами «Источник», «Запись», «Проверка», «Проблема», «Принятое решение». Даже если проблем нет, сохраните число проверенных строк и результат проверок.

**Проверьте себя:** вы знаете, какие строки допускаете к загрузке и как поступаете с остальными. Все изменения объяснимы и воспроизводимы.

## Шаг 8 Спроектируйте и создайте таблицы PostgreSQL

На основе своего описания модели напишите DDL в папке `sql`. Можно использовать отдельную схему, например `module_a`, внутри своей базы.

Для каждой таблицы определите:

1. Названия и типы столбцов.
2. Первичный ключ.
3. Обязательные значения.
4. Внешние ключи и ограничения, соответствующие смыслу данных.
5. При необходимости индексы для соединений.

Обязательно предусмотрите `stg_competency_html`, `stg_competency_event_link`, `stg_fact_results_enriched`. Остальные таблицы организуйте так, чтобы сохранить исходные сущности и тексты для последующих модулей.

Для обогащённого факта заранее запишите правило: что представляет одна строка и как сохраняется её идентификатор. Не позволяйте связи «одна компетенция — несколько событий» случайно умножить результаты участия.

Выполните DDL через SQL-редактор либо передайте свой SQL в psql. Если выбрали указанное ниже имя файла, из PowerShell в папке `student` можно выполнить:

```powershell
Get-Content -LiteralPath work/Rep1/sql/01_schema.sql -Raw -Encoding UTF8 |
    docker compose exec -T db psql -v ON_ERROR_STOP=1 -U student -d student
```

Команда выполняет ваш собственный SQL. Файл `01_schema.sql` вы должны написать самостоятельно. Для изменённых имени базы и пользователя скорректируйте параметры.

**Проверьте себя:** таблицы появились в вашей базе; их структура совпадает с документацией. Ограничения отражают реальные ключи и связи.

## Шаг 9 Реализуйте загрузку и обогащение факта

Напишите собственный загрузчик. Определите порядок загрузки с учётом внешних ключей: зависимые записи не должны попадать в БД раньше справочников, на которые ссылаются.

Продумайте следующие вопросы:

- Как загрузить данные без ручного копирования значений?
- Как передать строки с кавычками и специальными символами корректно?
- Что произойдёт при ошибке в середине загрузки?
- Что произойдёт при повторном запуске?
- Как хранить пароль отдельно от кода?

Используйте транзакции для связанных изменений. При работе через драйвер БД передавайте значения параметрами, а не подставляйте их в текст SQL конкатенацией.

Создайте обогащённый факт, добавив необходимые атрибуты компетенции, события и региона. Состав и способ получения атрибутов опишите. После объединения сравните количество записей и уникальных `result_id` с подготовленным фактом, объясните любое расхождение.

**Проверьте себя:** в базе есть исходные сущности и три обязательные таблицы. Повторный запуск не добавляет дубликаты и не требует ручного исправления данных.

## Шаг 10 Проверьте итоговую базу

Напишите SQL-проверки и сохраните их в папке `sql`. Выполните их на загруженной базе и включите фактические результаты в отчёт.

| Проверка | Что нужно установить |
|---|---|
| Обязательные поля | Нет ли пустых ключей и других недопустимых пропусков |
| Уникальность | Не повторяются ли ключи, включая пару компетенция–событие |
| Типы и диапазоны | Корректны ли значения года, места и других типизированных полей |
| Ссылочная целостность | Есть ли соответствующая запись справочника для каждого ключа |
| Сопоставление HTML | Все ли нужные ссылки связаны с событиями |
| Полнота загрузки | Совпадают ли ожидаемые и фактические объёмы после вашей очистки |
| Обогащение | Не потерялись и не размножились ли результаты |
| Текстовые источники | Сохранились ли тексты и связи с событиями/компетенциями |
| Повторный запуск | Остаётся ли результат стабильным |

Для пропусков укажите не только количество, но и долю от числа записей соответствующей таблицы. Объясните, какие пропуски критичны, а какие допустимы.

Одного сообщения «ошибок нет» недостаточно. Покажите проверку, число проверенных записей, число нарушений и вывод. Не придумывайте ошибки, если в чистом учебном наборе они не обнаружены.

**Проверьте себя:** другой человек может выполнить ваши запросы и получить те же результаты.

## Шаг 11 Подготовьте описание и сдайте работу

В `reports/model.md` завершите описание сущностей, ключей, атрибутов и правил связывания. Добавьте схему зависимостей таблиц.

В `reports/quality_report.md` включите:

1. Перечень использованных файлов и объёмы данных.
2. Правила преобразования типов и обработки проблем.
3. Результаты всех проверок с числами.
4. Найденные ограничения данных.
5. Вывод о готовности модели к следующему модулю.

В `work/Rep1/README.md` напишите инструкцию для проверяющего: откуда запускать команды, какие зависимости нужны, как настроить подключение и в каком порядке выполнять ваши скрипты. Укажите, какие таблицы и файлы появятся. Если ваш код меняет или очищает таблицы при повторном запуске, явно опишите это поведение.

Проверьте соответствие открытым критериям модуля А в `materials`. Убедитесь, что в коде есть комментарии к нетривиальным решениям, а в документации — фактическое состояние базы.

Передайте преподавателю папку `work/Rep1` и доступ к своей учебной базе согласованным способом. Если требуется внешний репозиторий, создайте Rep1 и настройте доступ по указанию преподавателя. Пароли, `.env` и `.venv` в репозиторий не добавляйте. Дашборд в этом модуле делать не нужно.

**Проверьте себя:** преподаватель может воспроизвести работу по вашей инструкции без догадок и ручного восстановления пропущенных шагов.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Docker недоступен | Запущен ли Docker Desktop, выбран ли режим Linux containers |
| Порт занят | Нет ли другой копии стенда; согласуйте другой POSTGRES_PORT |
| База не готова | Выполните `docker compose ps` и `docker compose logs db` |
| Неверный пароль | Используете ли свой .env; не меняли ли пароль в файле после инициализации БД |
| Python не находит библиотеку | Установлена ли она именно в .venv, тем ли Python запускается скрипт |
| Не найдены входные файлы | Текущая папка терминала и способ построения путей в вашем коде |
| Испорчена кириллица или первый заголовок | Кодировка чтения и наличие BOM |
| Ссылка события не открывается | Страницы событий не входят в набор; сопоставляйте URL с source_page |
| Строк стало больше после объединения | Уникальность ключей справа и выбранные поля соединения |
| Строк стало меньше | Использованный тип соединения, фильтры и несопоставленные ключи |
| Загрузка нарушает внешний ключ | Порядок загрузки и существование записи в справочнике |

Не устраняйте ошибки отключением всех ограничений или удалением непонятных строк без объяснения. Найдите причину, примите обоснованное решение и отразите его в отчёте.

Добавьте в неё по очереди точный дубликат, конфликтующий ключ, неизвестный регион, неверное числовое значение и несопоставленную ссылку. Проверьте реакцию своего решения и запишите результаты. Оригинальный учебный набор оставьте неизменным. Эти эксперименты выполняйте после основного упражнения, отдельно от трёхчасового прохода.
